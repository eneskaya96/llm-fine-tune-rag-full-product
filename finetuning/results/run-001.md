The failures share one cause: the model orders when it should ask. Training data
contained no example of an unavailable size, an ambiguous product name, or a
request too vague to act on, and 80% of it ended in a tool call, so "place the
order" became the default.

Concretely, on a menu listing `Cortado | S,M`, asked for "a large cortado", it
emitted `size: "L"`. On `Espresso | S`, asked for "medium espresso", it emitted
`size: "M"`. It did refuse "extra large latte" — it recognises a size word that
does not exist, but does not check the per-product size list.

The empty reasoning block also corrupts output. One generation opened
`<tool_call>` and closed `</think>`, mixing the two tag sets.

## Where the gain comes from

Two failure modes visible in the generations:

**Incomplete tool arguments.** The base model omits fields it was not asked
about, e.g. `{"name": "Doppio", "size": "S", "quantity": 1}` with no `milk` or
`extras`. The tuned model always emits the full schema.

**Asking instead of ordering.** For "Could I have a medium london fog?" the base
model replies *"Would you like it with whole milk or skim milk?"* and emits no
order. The tuned model places it.

## Known problems with this run

**The eval set is too easy, and 100% is the evidence.** It comes from the same
generator as the training data, so the dialogue templates are identical — only
the brand, menu, and prices differ. The model saw each phrasing pattern hundreds
of times in training. This run measures template recall, not generalisation. A
hand-written hard set (unusual phrasing, typos, longer dialogues, combined
difficulties) is needed before these numbers mean anything.

**The tuned model emits an empty `<think></think>` block before every answer.**
Qwen3's chat template inserts it, and building the training text with
`apply_chat_template` folded it into the target the model learned to reproduce.
Harmless for scoring, wasted tokens at serving time, and something the serving
layer has to strip. Fix by trimming it when building the training text.

**Tone is not measured at all.** There is one voice, so there is nothing to
compare against. A second adapter makes a discriminability test possible.
