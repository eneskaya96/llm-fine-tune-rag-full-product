# Run 003 — both voices, 12 categories

Changes from run 002: a `negation` category (extra ruled out, food declined,
one milk rejected while another is named), closing phrasings in `simple_order`
and `multi_item` ("that's it", "that's all"), comparative sizes ("whatever size
is biggest"), and shares trimmed from the categories whose asking habit
over-generalised. Tool-call share 70% → 72%.

Both adapters trained from the same generator, same hyperparameters, same
behaviour rules. Only the wording differs.

The two adapters differ by ±40 points on individual categories while landing
within one example of each other overall. They were trained on the same
dialogues with the same settings; only the phrasing differs. So most of that
per-category spread is sampling noise, not a property of either voice: at n=3,
one wrong answer is 33 points.

Treat the overall numbers as the result and the per-category column as a
pointer to what to inspect. Separating a real regression from noise needs
either more examples per category or several seeds per configuration.

## Known problems

**One real error worth naming.** Asked for "chai latte pls — the big one — w
oat", blunt emitted `milk: "whole"`. The customer said oat. The `negation`
category teaches that naming the default milk means recording it, and this looks
like that rule over-applied. Friendly gets the same example right.

**Tone is not scored here.** `exact_match` compares order items, not prose, so
these tables say nothing about whether either adapter sounds like its brand.
That is `scripts/tone_eval.py`'s job and has not been run against real
generations yet.

**The hard set is 37 examples.** Enough to expose failure modes, too small for
confidence intervals on any single category.
